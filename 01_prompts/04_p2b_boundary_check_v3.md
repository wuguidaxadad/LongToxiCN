# P2 边界复核（DeepSeek Flash 版 v3）

你只做一件事：对同一语义块内、已经圈出的相邻两条实例，判断它们该合成一条还是保持两条。不重新抽取，不判断伤害，不写简述，不改 Target。

## 什么是一条实例

一条实例 = 围绕 Target 连续完成**同一件事**的最大连续原文。"同一件事"只有这七种：

- 一项群体判断（连同它紧随的短理由、换个说法的重复、一句话带过的例子、直接结论）
- 一个完整案例（同一人物/事件的背景、行为、经过、台词、结果、紧接的收束评论）
- 一组并列的短证据（几个各只有一两句的事例、数据、引语，共同支持同一判断）
- 一个回到群体层的总结或诊断
- 一个限定或缩小范围的说法
- 一个反驳或纠正
- 一项应对主张（要求、建议、措施）

## 判断方法：默认合并，分开必须给出理由

对每个边界，先问：**右边开始的内容，是不是在做一件和左边不同的事？** 只有以下 6 种情况算"不同的事"，必须从中选一个，并原样引用右边触发这个切换的第一句：

| 代码 | 右边开始了什么 | 反例（不算） |
|---|---|---|
| `K1` | 一个有自己人物、起点和经过的**完整案例**（不是一句话带过的例子） | 左边判断后跟一句"比如某某就这样"——这是短依据，JOIN |
| `K2` | 案例讲完，**跳回群体层**作总结、诊断（"所以这类人都…"） | 案例里人物自己说的评价——还在案例内，JOIN |
| `K3` | **另一个人物或事件**的新案例 | 同一人物的事情继续发展、情况变好又变坏——JOIN |
| `K4` | **另一项群体判断**，谓词不同（从"懒"换到"贪"），不是上一项的理由、解释、例子、后果或结论 | 换个词重复、补一句解释、加个比较、说这个毛病由来已久或影响很大——JOIN |
| `K5` | **限定、反驳、纠正**开始（"但这只是少数""专家指出并非如此"） | 同一判断内的让步半句（"虽然…但是…"在一句里）——JOIN |
| `K6` | **应对主张**开始（要求、建议、措施、责任安排） | 判断末尾顺带一句"该管管了"——JOIN；一组并列建议中的下一条——看是否换了谓词，多数 JOIN |

以下情况**一律不是理由**：句号、换行、引号、说话者变了、出现"但是/然而"、故事推进了一步、role 标签不同、每句都能单独概括、左右都"很重要"。

**K4 的硬条件**：必须分别写出左边的谓词和右边的谓词，各一句话，格式"Target + 怎么样"。两句如果说的是同一个特点（只是措辞、程度、来源、时间不同），或者右边是在解释左边为什么如此、有多严重、由来多久，就不是 K4，JOIN。例：左"安溪有诈骗之乡的恶名"、右"安溪诈骗积年陈弊、由来已久"——同一个特点，JOIN；左"山东男人不下厨"、右"山东男人不认可轮流做饭的分工"——同一个特点，JOIN；左"海南人保守狭隘"、右"香港人兼具东西方性格"——对象都换了，K4。

**K4 只用于评价性判断**。连续的中性材料——数据、统计、病症/症状描述、法律条文、历史经过、场景和情节描述——每句说的事实自然不同，但它们不是"另一项群体判断"，而是同一组材料，中间 JOIN。只有当材料之后出现一句**由此得出的评价、诊断或威胁化**（"可见……""所以这类人……""这成为威胁社会的危险因素"），才在那句前面 K2 或 K4 分开；数据本身和评价句之间的这条边界必须保住。

**并列短证据**：几个各只有一两句的事例连着出现（"某甲这样，某乙那样，去年还有个……"），它们是一组，JOIN；只有其中某个展开成了有经过的完整案例，才在它前面 K1、后面 K2/K3。

**清单**：编号列表里每一项是独立的群体判断（"1、河南人…… 2、湖北人……"）→ 每项之间 K4。同一项内部的句子 → JOIN。

## 自检

- 每个 KEEP 都引用了右边的触发句，且那句确实做了代码描述的事；
- 如果你想 KEEP 但六个代码都套不上，那就是 JOIN；
- 合并后超过一件事了吗？没有就对了。

## 输出

只输出严格 JSON：

```json
{
  "task_key": "输入的 task_key",
  "decisions": [
    {"boundary_id": "O001|O002", "decision": "JOIN"},
    {"boundary_id": "O002|O003", "decision": "KEEP", "code": "K1", "trigger": "原样引用右边第一句"},
    {"boundary_id": "O003|O004", "decision": "KEEP", "code": "K4", "trigger": "原样引用右边第一句", "left_predicate": "Target + 怎么样", "right_predicate": "Target + 怎么样"}
  ]
}
```

`decisions` 必须覆盖输入的每个 `boundary_candidates`，顺序一致。`decision` 只能是 `JOIN` 或 `KEEP`；`KEEP` 必须带 `code`（K1–K6）和 `trigger`；`K4` 还必须带 `left_predicate` 和 `right_predicate`。不输出其它内容。
